# 実装計画: 画面デザインの刷新（Platform）

**ブランチ**: `005-ui-design` | **日付**: 2026-11-05 | **仕様**: [spec.md](./spec.md)

**入力**: `/specs/005-ui-design/spec.md` の機能仕様（2026-11-05 に明確化済み）

## 概要（Summary）

002・003 の画面を、ボストン地下鉄の駅の案内に根ざした見た目（「Platform」）に作り直す。色・書体・文字の大きさ・間隔をデザイントークンとして 1 か所（`src/app/globals.css`）に定義し、明るい表示と暗い表示の値を持たせる。暗い表示は OS の設定に合わせ、ヘッダーの切り替えで手動でも選べる。DB は変えない。内部 API は、路線図のために `GET /api/static/stops` に路線パターンごとの駅の並びを足すだけ（後方互換）。

大胆にするのは 1 か所だけ: **到着表示を、ホームの発車標のような濃い板に大きな琥珀色の残り分数で出す**。それ以外は静かに、路線色の帯・路線図の形・余白と見出しで構造を示し、カードの枠を減らす。

## 技術的な前提（Technical Context）

**言語/バージョン**: TypeScript（strict）、Node.js 24.x

**主な依存関係**: Next.js（App Router）、Tailwind CSS v4、MapLibre GL JS、Apache ECharts、TanStack Query。追加: `@fontsource-variable/overpass` 5.3.0（書体の自前の配信）、`@axe-core/playwright` 4.14.0（開発用。アクセシビリティの自動の検査）

**ストレージ**: なし（表示の選択はブラウザの localStorage にだけ残す）

**テスト**: 既存の E2E（002・003）を通す。新しい振る舞いの E2E、axe-core の検査（明るい・暗い）、表示用の計算の単体テスト。見た目は画像で比べず、スクリーンショットで確かめる（spec.md の TR-001〜TR-006）

**実行環境**: 変わらない（Cloud Run の web）

**プロジェクトの種類**: Web アプリ（Next.js 一体型）の画面だけ

**性能目標**: 初回表示 3 秒以内を保つ。書体は可変フォント 1 つ（latin のサブセット、約 40KB）だけを先に読み込む

**制約**: 画面は英語。フッターの出典表記を保つ。MBTA のロゴと公式の見た目を真似ない。ブラウザから外部のフォントの配信元に通信しない（FR-013）。ビルド時に環境ごとの値を入れない（憲章 VI）

**規模/範囲**: 画面 9 つ（`/`, `/stations`, `/stations/[stopId]`, `/alerts`, `/status`, `/analytics/*` の 4 つ）と共通のヘッダー・フッター

## デザインの決定（詳細は research.md、値は contracts/design-tokens.md）

### 色

明るい表示（駅のコンクリートと案内板）と暗い表示（夜のホーム）の 2 組。路線色は MBTA の路線色を使い、暗い表示ではコントラストを満たすよう明るくした値に替える。強調の色（琥珀）は到着表示の残り分数だけに使う。重要度は色ではなく**斜めの縞（警戒の帯）とアイコンと文言**で示す（路線の赤・橙と混同しないため）。

### 書体

**Overpass**（米国の道路標識の書体の系譜。OFL）の可変フォント 1 つ。見出しは 800、本文 400、強調 600。時刻・分数・件数はすべて等幅の数字（`tabular-nums`。Overpass で幅がそろうことを確かめた）。大きさの段階は 1.25 倍（13 / 16 / 20 / 25 / 31 / 39 / 49px）。すべて文の形（sentence case）で、大文字だけのラベルは使わない。

```text

│   ├── alerts/                        # 重要度の縞とアイコン
│   ├── status/                        # 状態の一文
│   ├── analytics/                     # 要点の一文、カードをなくした区切り
│   └── charts/theme.ts                # グラフの色を明るい・暗いの両方に（003 で検証した配色を保つ）

├── unit/display/*.test.ts             # 表示用の計算
├── unit/theme.test.ts
├── e2e/theme.spec.ts                  # 表示の切り替え（TR-006）
├── e2e/a11y.spec.ts                   # axe-core（TR-004。明るい・暗い）
```

**構成の決定**:
- デザイントークンは CSS 変数で定義し、Tailwind v4 の `@theme inline` で名前を付けて使う。部品の中に色の値を書かない
- 暗い表示は、`html` の `data-theme` 属性（`light` / `dark`。「OS に合わせる」のときは付けない）と、`prefers-color-scheme` のメディアクエリの両方で切り替える。Tailwind の `dark:` は使わず、トークンの値が入れ替わるだけにする
- 表示用の計算はすべて `src/lib/display/` の純粋関数にし、部品は描くだけにする（憲章 IV）

## 既存の振る舞いの変更（E2E を直すもの）

- **到着表示の秒のカウントダウン**: いまは各便に「6:27」と「6 min」の 2 つを出し、E2E（`stations.spec.ts`）は秒の表示（`arrival-clock`）で毎秒減ることを確かめている。FR-006 で表し方を 1 つにするので、**残りが 2 分未満の便だけ「1:23」のように秒まで出し、それ以外は「n min」**にする（1 つの便には常に 1 つの表し方）。E2E は、時計を進めて「n min」が減ることと、2 分未満の便の秒が減ることを確かめる形に直す。`data-testid` は `arrival-countdown` に 1 つにまとめる
- **路線のボタン**: 凡例に置き換える。E2E の `route-filter-<id>` は凡例の各行に付け、`aria-pressed` も保つ
- **駅の一覧**: `station-group-<route>` は路線図の各路線に付ける。Green は 1 つの路線図（`station-group-Green`）になるので、E2E の「Park Street が 5 路線に出る」は「Red と Green の 2 つの路線図に出る」に直す
- **分析の数字のタイル**: 要点の文の中の数字に、同じ `data-testid`（`stat-…-value`）を付ける

## 複雑さの記録（Complexity Tracking）

| 原則からの逸脱 | 必要な理由 | より単純な案を採らなかった理由 |
|---|---|---|
| 到着表示の板は、明るい表示でも濃い色 | 発車標を思わせる、この画面でいちばん大事な数字を目立たせる 1 か所。明るい表示と暗い表示の両方でコントラストを確かめる | 明るい表示で白い板にすると、ほかの部分と同じ重さになり、残り分数が目立たない |
| 表示の選択を描画の前に当てるインラインのスクリプト | 読み込みの途中で違う表示が一瞬出ないようにする（FR-014） | 描画のあとに React で当てると、暗い表示の人に明るい画面が一瞬出る |
